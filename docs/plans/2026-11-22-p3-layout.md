**Goal:** Give the docked assistant a full-screen mode that behaves as a modal (focus trap, inert page, Escape back to the previous layout), a chat history column in full screen (drawer on narrow screens), a layout menu to switch sidebar / window / full screen, a persistent list variant of `SessionSwitcher`, a docked width that always leaves the page a usable width, and the composer toolbar as a row under the editor (deferred from P2a to P3).

**Architecture:** Everything is built on the existing `AssistantLayoutProvider` / `AssistantShell` / `AssistantWorkspace` (`src/react/assistant/`) and `SessionSwitcher` (`src/react/components/session-switcher.tsx`); `ChatWindow` / `FloatingChatUI` are not touched (D2). Full screen is a third `AssistantLayoutMode`; the shell only offers it when the app lists it in the new `modes` prop (D1), so without config the DOM and behavior stay those of 0.22.0. The return target from full screen is the existing `defaultMode` (D3) — no new state. The modal behavior lives in one internal hook `useModalSurface`. The history column renders the new `SessionSwitcher variant="list"`. The children of the shell keep their React position in every mode, so switching layouts never remounts the chat (composer text, scroll position, running stream survive). No new export names: only new members on existing types (D14).

**Tech Stack:** TypeScript strict ESM (NodeNext), React 18/19, vitest + Testing Library (jsdom), Bun.

**Spec:** Package list of this work stream (session 68e83dcc, P3: "Vollbild mit Fokusfalle, Verlaufsleiste, Moduswahl, Session-Switcher als Liste, Breite passend zum Viewport") and the omnify analysis ("Paket 3: Layout": modes in `AssistantShell`, Escape returns to the previous mode, history column 260 px / drawer below 900 px, `--cm-chat-max-width`, `ModePicker`, `SessionSwitcher variant="list"` with `onSelect`, `widthLimits.reserveContent`). ## Review Focus

1. **Who owns Escape in full screen.** A completion list, the plus menu, the layout menu, an inline rename, a `ConfirmDialog` (window listener, portaled) and the narrow history drawer each consume Escape first; only a free Escape leaves full screen, and it restores the previous layout instead of closing (Task 3 `escape ownership`, Task 6 `drawer escape`).
2. **`inert` bookkeeping.** Entering full screen marks every sibling up to `<body>` inert and remembers its previous value; leaving, closing, unmounting the shell or switching layout restores exactly those values; a portal opened later (`ConfirmDialog`) is not inert; an element that was already inert stays inert (Task 3 `restores inert exactly`).
3. **No remount on layout change.** Sidebar → full screen → window → sidebar keeps the same composer element, its text and the message list; the history column is inserted before the frame without shifting the children's React position (Task 3 `same composer in every layout`).
4. **Stored state across versions.** A 0.22.0 reader of a stored `mode: "fullscreen"` falls back to its default; this version never stores `defaultMode: "fullscreen"`; a stored layout outside the shell's `modes` falls back (Task 1 `parse`, Task 4 `stored mode outside modes`).
5. **Drawer on narrow screens.** Opening moves focus into the drawer and makes the conversation inert; Escape, backdrop and a pick close it; a pick focuses the composer, Escape/backdrop focus the toggle; growing past 900 px with the drawer open leaves a consistent state (Task 6).
6. **Zero-config DOM.** Existing shell, workspace, switcher and toolbar tests unchanged; new markup appears only with `modes` including `'fullscreen'`, `variant="list"`, `minPageWidth` or `composer.layout`.

**Interfaces:**
- Consumes: `AssistantLayout.mode === 'fullscreen'`, `restoreMode()` (Task 1).
- Produces (internal):
```ts
/**
 * While `active`: locks body scroll, marks every sibling on the path from
 * `ref` up to <body> inert (restoring each element's own previous value
 * afterwards), keeps Tab inside `ref`, and calls `onEscape` for an Escape
 * nobody else consumed. Elements added to <body> later (portaled dialogs)
 * are left alone.
 */
export function useModalSurface(ref: RefObject<HTMLElement | null>, options: { active: boolean; onEscape(): void }): void;
```
  - Escape is ignored when `event.defaultPrevented`, when `event.isComposing`, or when an element matching `[role="alertdialog"], [aria-modal="true"]` exists outside `ref` (e.g. `ConfirmDialog`, which listens on `window` after us). Listener: `document` `keydown`, bubble phase (React handlers of the composer, plus menu and layout menu have run and called `preventDefault`).
  - Tab: focusables = `button, [href], input, select, textarea, [contenteditable="true"], [tabindex]` inside `ref`, minus `:disabled`, `[tabindex="-1"]`, and anything inside `[hidden]` or `[inert]`; wrap first↔last; skip when another modal (as above) is open.
- Produces (public): `AssistantShellLabels.fullscreen?: string` (`'Full screen'` / `'Vollbild'`, used as menu entry in Task 4 and as the dialog's description), no other new prop in this task. The full-screen frame takes `labels.title` as its name.
- Shell behavior in full screen:
  - `aside[data-mode="fullscreen"]` inline: `position: fixed; inset: 0; width: 100vw; height: 100dvh; maxWidth: none; maxHeight: none`; no resize handle, no window handles, no rail, no bubble, header not draggable (no `tabIndex`, no `windowHeader` label); `insetProperty` `0px`; `[data-assistant-main]` not hidden (it is inert instead).
  - `[data-element="frame"]` gets `role="dialog" aria-modal="true" aria-label={labels.title}` only in full screen (an `aside` may not carry `role="dialog"`).
  - Header buttons in full screen: `headerActions`, clear, close; no detach/dock/collapse (Task 4 adds the layout menu).
  - `useModalSurface(shell, { active: ui.open && mode === 'fullscreen', onEscape: ui.restoreMode })`.
  - Shortcut `toggleLayout` in full screen calls `restoreMode()` (D6); `toggle` (mod+I) closes as everywhere.
  - Every `!sidebar` that today means "detached window" becomes `mode === 'floating'` (`useFloatingPanel` `enabled`, placement, handles, bubble, header drag).
- CSS (styled only): `[data-mode="fullscreen"]` no border, radius or shadow; `[data-mode="fullscreen"] [data-element="body"] { width: 100%; max-width: var(--cm-chat-max-width, 960px); margin-inline: auto; }` (D13).

## Out of scope

- `ChatWindow` / `FloatingChatUI` (the portal widget): no full screen there (D2).
- `ChatWindowVisibilityContext` from `AssistantShell` (stop recording, lock the switcher while the shell is closed or collapsed; omnify `chat-surface-visibility.tsx`): a default behavior change, own small package.
- Detached window opening bottom-center, full-page window below 640 px, overlay scrollbars (`use-chat-scrollbars.ts`), `ChatThemeScope`, header double-click to maximize (D5), a dedicated full-screen shortcut (D6), `confirmDelete` / `sort` props on `SessionSwitcher` (D9).
- `glirastes/embed` options for `modes`, `historyPane`, `minPageWidth`, `composer.layout` (later, own note).
- Message footer, follow-ups placement, activity log (P6).

## Decisions

- **D1:** Full screen is opt-in through `AssistantShell`/`AssistantWorkspace` `modes` (default `['sidebar','floating']`) — keeps the zero-config DOM and one prop switches it on — rejected: full screen always offered, or a separate `fullscreen` boolean next to a picker prop.
- **D2:** Full screen, layout menu and history column exist only in `AssistantShell`/`AssistantLayout`, not in `ChatWindow`/`FloatingChatUI` — smallest surface; the omnify analysis already targeted the shell — rejected: a parallel `mode="fullscreen"` on `ChatWindow`.
- **D3:** The return target is the existing `defaultMode`; full screen never becomes `defaultMode`; close + reopen returns to the normal layout; an open full screen survives a reload — no new state, matches omnify's reload behavior — rejected: omnify's separate `lastNormalMode` ref and reopening in full screen after a close.
- **D4:** A built-in layout menu (`menuitemradio`) replaces detach/dock only when `modes` contains `'fullscreen'`; it is not exported — matches omnify's `ChatModePicker` — rejected: a separate maximize button, an exported `ModePicker`.
- **D5:** No header double-click to maximize; double-click keeps resetting the detached window — keeps zero-config behavior — rejected: omnify's double-click → full screen.
- **D6:** No new shortcut action; `toggleLayout` (alt+shift+D) leaves full screen — smallest surface — rejected: a `toggleFullscreen` `ChatShortcutAction`.
- **D7:** Full screen is a modal: `role="dialog" aria-modal` on the frame, inert siblings, body scroll lock, Tab wrap; Escape restores the previous layout instead of closing; nested Escape owners win — omnify's behavior — rejected: Escape closes the chat; a focus-trap dependency.
- **D8:** History column only in full screen; default content is the chat list when the chat keeps several; one `historyPane` prop (`false` / node); 260 px and the 900 px drawer breakpoint are fixed; open state not persisted — omnify's values, smallest surface — rejected: width/breakpoint props, a history column in sidebar mode.
- **D9:** `SessionSwitcher` gains only `variant: 'dropdown' | 'list'` and `onSelect` — it already sorts by `updatedAt` and uses the themed `ConfirmDialog` — rejected: omnify's `confirmDelete` hook and a `sort` prop.
- **D10:** List rows show the title with a `title` tooltip and no date; the dropdown markup stays as is (no tooltip added) — keeps zero-config DOM, matches omnify's list — rejected: tooltips added to the dropdown rows too.
- **D11:** `minPageWidth` on the shell, default 0, measured against the shell's row — zero-config unchanged, works with left navigation — rejected: omnify's fixed `viewport − 520` default and a `widthLimits.reserveContent` on the layout provider.
- **D12:** The resize handle's maximum follows the width that can render — fixes a wrong `aria-valuemax`/End target; only differs when the row is narrower than `maxWidth` — rejected: leaving the handle at `maxWidth`.
- **D13:** Full-screen reading width via the CSS custom property `--cm-chat-max-width` (default 960px) in `styles.css` only — no theme API change — rejected: a new `ChatTheme` key.
- **D14:** No new export names (menu internal, no `ChatThemeScope`; the shell already puts `themeVars` on its root and the column is inside it) — smallest surface — rejected: exporting `ModePicker` and `ChatThemeScope`.
- **D15:** New members of `AssistantShellLabels` and `AssistantShellIcons` are optional — apps that build a complete labels object keep compiling — rejected: required members.
- **D16:** `modes` also restricts: one entry hides the layout control and shortcut; a stored layout outside `modes` falls back — the natural meaning of the list, no extra prop — rejected: `modes` as a pure menu filter.
- **D17:** `composer.layout: 'stacked'` (P2a moved toolbar placement to P3), default `'inline'` — keeps the default composer row, matches omnify's toolbar under the editor — rejected: making stacked the default, or leaving it to `components.ComposerToolbar` only.
