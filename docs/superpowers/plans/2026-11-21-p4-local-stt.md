# P4 Local STT Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transcribe a finished browser recording inside the consumer's own Node server with Parakeet TDT 0.6b v3 int8 (sherpa-onnx), through a new `transcribe` option on `createRecordingTranscriptionHandler`, a new ESM-only subpath `glirastes/server/stt-local`, and a CLI command `glirastes stt pull` that fetches the pinned model files.

**Architecture:** The handler keeps its checks (auth, content type, language, size) and, in `transcribe` mode, decodes the WAV itself and hands `Float32Array` samples to a provider-neutral `RecordingTranscriber`. `glirastes/server/stt-local` implements that function: it preloads the native addon on the main thread, runs one worker per process that loads the model lazily, cuts long audio at VAD silence midpoints into chunks of at most 20 s and decodes them one after another, with cancellation checked between chunks and `worker.terminate()` only as a hard stop. `glirastes stt pull` downloads five sha256-pinned files atomically into the model directory; nothing is ever downloaded at runtime.

**Tech Stack:** TypeScript (ESM, NodeNext), Bun, Vitest, `node:worker_threads`, `sherpa-onnx-node` 2.0.1 (optional peer, CJS, N-API), Next.js 15 route handlers, GitHub Actions.

**Spec:** The P4 scope points 1–7 approved by the owner ("passt so", session `68e83dcc…`, 2026-11-21) plus section 6 "Required design changes" of the P4 feasibility spike report (2026-11-21, kept in the session scratchpad, not in the repo). Every binding value of both is copied into Global Constraints below; the executor does not need the scratchpad. Algorithm reference from the spike: `splitAtSilence` / `quietestCut` (reproduced as the algorithm in Task 3) and the RIFF walker (Task 1).

- The main thread loads the addon (the dynamic import above) **before** the first worker starts (~40 ms, ~10 MB, no model); without it a restarted worker fails on linux-arm64 with `Module did not self-register`.
- Recognizer config: `featConfig { sampleRate: 16000, featureDim: 80 }`, `modelConfig { transducer { encoder, decoder, joiner }, tokens, numThreads, provider: 'cpu', debug: 0, modelType: 'nemo_transducer' }`. `numThreads` default **2**, configurable (integer 1–16).
- VAD config: `sileroVad { model, threshold: 0.5, minSpeechDuration: 0.25, minSilenceDuration: 0.5, maxSpeechDuration: 19, windowSize: 512 }`, `sampleRate: 16000`, `numThreads: 1`, `provider: 'cpu'`, `debug: 0`; buffer seconds `Math.ceil(samples.length / 16000) + 5`; feed in 512-sample windows, drain after each, `flush()`, drain again.
- Chunking (enforced in our code, the VAD's own max is not a hard limit): audio ≤ 20 s (≤ 320 000 samples) skips the VAD and is decoded whole; longer audio is cut from the **original** samples at midpoints between consecutive VAD speech spans, filled greedily up to 20 s, each chunk ≥ 2 s; when no midpoint fits, cut at the quietest 30 ms frame (480 samples, hop 240) in the last 8 s of the window; 0.3 s (4 800 samples) padding before the first and after the last span; never decode the VAD's trimmed segments; non-empty chunk texts trimmed and joined with single spaces; VAD finds no speech → `''`.
- Gain: before VAD and decode, if `0 < peak < 0.1` (peak = max |sample|), multiply by `min(0.5 / peak, 20)`; otherwise unchanged (model card; upstream sherpa-onnx#4024).
- Warmup: after model load the worker decodes 1 s of silence (`new Float32Array(16000)`).
- Cancellation: the worker checks a per-job `SharedArrayBuffer` cancel flag and the job deadline between chunks and stops with an abort. `worker.terminate()` only when a cancelled or overdue job has not answered within `hardStopGraceMs` (default 5 000); then the next job spawns a fresh worker lazily (expect 1–9 s model reload).
- Load: one worker per process; one job at a time; at most `maxQueue` (default 4) waiting jobs, beyond that `TranscriptionUnavailableError` → handler answers **503**. Handler `timeoutMs` default **120 000** in `transcribe` mode; the `url` mode default stays 45 000.
- Fallback mode `mode: 'inline'`: no worker, `OfflineRecognizer.createAsync` + `decodeAsync` on the libuv threadpool (verified not to block the event loop); same chunking and between-chunk cancellation; no hard stop.
- WAV input: walk RIFF chunks (no 44-byte assumption, skip unknown chunks such as `LIST`/`FLLR`, honour odd-size padding), require `fmt ` format 1 (PCM), 1 channel, 16 000 Hz, 16 bits; anything else → **415**. Samples are `int16 / 32768`.
- Memory, to document: about 1.2 GB steady, up to about 1.6 GB per process with 20 s chunks; plan a **2 GB** container limit.
- Model storage: directory = `GLIRASTES_MODEL_DIR`, else `$XDG_CACHE_HOME/glirastes/models`, else `~/.cache/glirastes/models`. Never shipped in the npm tarball, never fetched at runtime.

## Review Focus

1. **WAV with a lying `data` size** (0xFFFFFFFF from streaming writers, larger than the file, or an odd byte count): decode up to the end of the buffer and drop a trailing odd byte, never throw a RangeError. Test in Task 1.
2. **Concurrent first requests while the model is still loading**: exactly one worker spawn and one model load (two loads would need ~2.4 GB); all callers wait on the same load. Test in Task 5.
3. **Next.js dev HMR re-evaluating the route module**: a second `createLocalTranscriber` call with the same options in the same process reuses the existing instance (process-wide registry on `globalThis[Symbol.for('glirastes.stt-local')]`) instead of a second 1.2 GB worker. Test in Task 5.
4. **Client disconnect mid-transcription** (`request.signal` aborts): the job is cancelled between chunks, its queue slot is freed, the next job runs on the warm worker, no hard stop. Tests in Tasks 1 and 5.
5. **Worker dies unexpectedly** (native crash, OOM, `exit` without answer): the running job rejects with `SttLocalError` `worker_failed`, queued jobs run on a lazily respawned worker, nothing hangs. Test in Task 5.

### Task 3: Chunk planning and gain (pure functions)

**Files:**
- Create: `src/server/stt-local/chunking.ts`, `src/server/stt-local/gain.ts`
- Test: `src/server/stt-local/__tests__/chunking.test.ts`, `gain.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export const SAMPLE_RATE = 16000;
  export const MAX_CHUNK_SAMPLES = 20 * 16000;
  export type Span = readonly [start: number, end: number];       // sample indices, end exclusive
  export function needsVad(sampleCount: number): boolean;          // > MAX_CHUNK_SAMPLES
  export function planChunks(samples: Float32Array, speech: readonly Span[]): Span[]; // [] when speech is empty
  export function normalizeGain(samples: Float32Array): Float32Array;                 // new array only when scaled
  ```
- Algorithm (from the spike's validated `splitAtSilence`; signature does not determine it):
  ```
  pad = 4800; cuts = midpoints floor((speech[i-1].end + speech[i].start) / 2)
  start = max(0, speech[0].start - pad); end = min(n, speech.at(-1).end + pad)
  while end - start > MAX:
    fit = cuts with start + 2*16000 < c <= start + MAX
    cut = fit.length ? fit.at(-1) : quietest30msFrame(samples, start + MAX - 8*16000, start + MAX)
    push [start, cut]; start = cut
  push [start, end]
  quietest30msFrame: frames of 480 at hop 240, min sum of squares, return frame start + 240
  ```

- [ ] **Step 1: Write failing tests:**
  - `needsVad is false at exactly 20 s and true one sample later` (320 000 / 320 001).
  - `cuts at silence midpoints and keeps every chunk at most 20 s`: 80 s of samples, spans every 15 s with 1 s gaps → every chunk length ≤ 320 000, every cut equals a midpoint, first chunk starts at `span0.start - 4800`.
